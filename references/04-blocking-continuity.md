## 空间确认硬门

任何重要人物关系、多人互动、关键道具位置、摄影机几何关系，都必须先确认空间。空间确认不是可选优化，而是分镜与提示词写作前的硬性Gate。

执行顺序必须是：

```text
锁定场景结构 → 建立坐标与方向 → 锁定人物和道具位置
→ 建立关系轴线与运动轴线 → 标出各SHOT摄影机位置
→ 检查可见性、遮挡和屏幕左右 → 才能拆CUT和写提示词
```

禁止先设计好看的机位，再让人物无理由转向摄影机或瞬间移动到适合构图的位置。

如果用户已提供并确认场景资产卡、站位图、前一镜结束状态或固定空间设定，直接继承，不重复要求确认；但仍必须在内部完成空间表和CUT几何检查。

## 必须画图的情况

以下任一条件成立，必须输出或内部建立俯视调度图：

- 两个或更多故事角色参与互动，即使部分SHOT不同时同框。
- 存在距离、遮挡、追逐、对峙、拥抱、递交、打断、注视、推拉或攻击关系。
- 存在明确的左、右、前、后、内、外、上下层级、靠近或远离关系。
- 关键道具需要放在具体表面、被具体角色拿取或在镜头间改变归属。
- 摄影机从哪个方向拍会影响轴线、视线、屏幕左右或信息可见性。
- 用户要求调整站位、朝向、距离、道具位置或镜头方向。
- 模型容易左右颠倒、前后错位、把人物并排放错或让人物突然面向镜头。
- CUT需要从正面切到过肩、反打、侧面、主观视角或高低机位。

可以跳过：

- 单人且无关键道具、无方向要求的纯表情特写。
- 无人物关系的纯环境镜头。
- 无具体空间位置要求的抽象插入镜头。

跳过时必须记录：

```text
已确认位置：本次范围无需位置图，原因：场景只有单人特写，无关键道具落点和人物关系。
```

## 场景坐标与主视角轴线

优先继承用户提供的场景图、资产卡和固定锚点，不凭空重建场景。

每个复杂场景建立稳定方向：

```text
北：场景深处／窗户／床头／舞台
南：入口／走廊／摄影机常用起始侧
东：右侧固定物／桌／侧门
西：左侧固定物／柜／另一出口
```

同时记录：

- 场景长度、宽度、高度或相对比例。
- 门、窗、床、桌、柱、屏风、楼梯等固定锚点。
- 人物互动轴线。
- 人物运动轴线。
- 摄影机允许活动区。
- 不可越过的墙体、家具和遮挡物。

若用户使用自定义坐标，按其规则记录，例如：

```text
整体空间：X 00—20，Y 00—15，Z 00—08
椅子：坐标02.12.03，朝东，比例1.0
人物A：坐标05.09.00，朝北
摄影机C1：坐标05.02.02，朝北
```

不得使用“左边一点”“大概在后面”“肩头或木桩上”等多解状态。

## 人物、道具与摄影机位置

### 人物

每名人物必须锁定：

- 绝对或相对位置。
- 与固定场景锚点的距离。
- 身体朝向。
- 头部与视线目标。
- 站、坐、跪、躺或支撑状态。
- 前景、中景、后景层级。
- 专属背景。
- 与其他人物的左右、前后、距离和遮挡关系。

### 道具

关键道具必须锁定：

- 所在表面或持有人。
- 具体位置、高度和朝向。
- 持物手、接触点和归属。
- 打开、关闭、破损、点燃、倒空等物理状态。
- 下一镜是否仍可见。

禁止漂浮、无过程换手、无过程消失或出现在错误表面。

### 摄影机

每个SHOT必须写清：

- 摄影机编号C1、C2、C3……
- 坐标或相对位置。
- 朝向。
- 位于关系轴线哪一侧。
- 景别、角度、高度和焦段。
- 主体位于画面左侧还是右侧。
- 前景遮挡物及其是否虚焦。
- 相比上一机位的角度变化。
- 当前机位能够看见和不能看见的信息。

## 空间确认输出格式

信息不完整且会改变人物关系、机位或CUT时，先输出：

```markdown
## 位置关系确认：场景 {N}

我先锁定人物、道具和摄影机位置。请检查后回复 `确认位置`，或直接指出要修改的项目。

**主视角轴线**
- 北：
- 南：
- 东：
- 西：

**固定场景锚点**
- 门／窗／床／桌／柱／屏风：

**人物与道具**
- A／角色名：坐标或功能区、朝向、视线、姿态、专属背景。
- B／角色名：
- P1／道具名：所在表面、位置、高度、状态。

**主要相互位置关系**
- A在B的什么方向，距离多少。
- 谁在谁的左前方、右后方。
- 谁遮挡谁，遮挡到什么程度。
- 入口、出口与人物的前后关系。

**摄影机位置**
- SHOT 1／C1：位置、朝向、轴线侧、主体屏幕位置。
- SHOT 2／C2：位置、朝向、轴线侧、相比C1的变化。
- SHOT 3／C3：

**关键限制**
- ⚠️不能互换左右。
- ⚠️不能越轴。
- ⚠️不能把角色移动到错误固定背景。
- ⚠️道具不能漂浮、换手或改变表面。
```

随后给出俯视SVG、ASCII、Mermaid或其他清晰示意。没有可视化工具时，文本俯视图必须仍能判断方向、距离和机位。

## 确认与停机规则

空间信息缺失且存在多种合理布局时，输出空间确认后停止，不同时输出正式分镜、故事板或视频提示词。

用户明确回复以下之一后继续：

- `确认位置`
- `位置确认`
- `位置对`
- 其他明确表示空间关系正确的话

如果用户修改位置，更新全部受影响的人物、道具、摄影机和轴线，再次等待确认。

以下情况不重复停机：

- 用户已经明确锁定位置。
- 已有通过审核的场景资产卡或站位图。
- 前一镜结束状态已经唯一确定当前布局。
- 用户要求直接按已有设定继续，且没有相互冲突的信息。

此时开头记录：

```text
已确认位置：是，继承自[具体资产／上一镜／用户确认内容]。
```

## 移动轨迹与接触关系

人物移动写成：

```text
起点坐标／功能区 → 连续运动方向 → 经过的障碍或节点 → 终点坐标／功能区
```

同时写清：

- 身体重心。
- 视线目标。
- 运动方向和速度。
- 持物手。
- 是否绕过固定障碍。
- 到达后朝向。

推、拉、抓、递、踩、坐、抬、开门或操作道具写成：

```text
执行者 → 使用的手／脚／道具 → 接触目标 → 接触位置 → 力量方向 → 动作后的状态
```

不得只写“抓住”“踢开”“递给”，把关键物理关系交给模型猜测。

## 相邻镜头机位连续性

所有相邻SHOT同时执行 `13-cut-shot-geometry.md`：

- 同一主体机位角度原则上至少变化30度。
- 禁止切到相邻机位、相邻景别或近似构图。
- 每次CUT至少改变两个有效视觉变量。
- 摄影机不得无理由越过180度关系轴线。
- 屏幕左右、视线方向和运动方向必须连续。
- 从正面切过肩时，必须明确从人物哪一肩外侧拍摄，以及摄影机仍处于轴线哪一侧。

禁止使用“摄影机在人物背后”这种不完整描述。应写：

```text
摄影机从上一镜人物左前方移动到人物左后方约45度，从左肩外侧拍向门口，仍位于人物关系轴线左侧。
```

## 跨镜与跨段状态继承

下一镜和下一段必须继承：

- 人物位置和相对距离。
- 身体朝向、头部方向和视线目标。
- 服装、发型、湿水、污渍、战损和情绪烈度。
- 坐、站、跪、躺、被捆、醉酒、虚弱等身体状态。
- 持物手、支撑手、接触关系和道具归属。
- 门窗、床幔、灯具和机关开合状态。
- 未完成动作的方向、速度和当前进度。
- 主光方向、色温和环境声。
- 上一镜已经产生的剧情结果。

下一镜的“起始状态”必须同时包含仍在画面中的旧主体和新主体，不能只写新出场人物。

禁止：

- 上一镜已抬头，下一镜重新抬头。
- 上一镜已看见目标，下一镜重新寻找。
- 上一镜仍被捆，下一镜无过程揉手腕或自由行走。
- 上一镜道具在右手，下一镜突然到左手。
- 上一镜人物位于床外侧，下一镜突然到床内侧。

生成阶段如需首尾重叠，只能作为剪辑把手；最终成片删除重复静帧、动作和台词。不得把生成重叠误写成剧情重复。

## 信息可见性

空间成立不等于信息可见。每个SHOT必须检查：

- 当前景别能否看清关键细节。
- 逆光是否遮掉面部信息。
- 前景人物是否遮挡主体。
- 虚焦人物是否被错误赋予关键动作。
- 手部、道具和接触点是否在画面内。
- 摄影机是否实际看得到人物所描述的绳结、瞳孔、伤口或机关。

例如：

- 中远景逆光过肩镜头不能同时展示瞳孔内部碎片。
- 双手反捆在背后时，人物不能用目光直接看见背后的绳结。
- 人物已经面向墙角观看凝聚过程，下一镜不能再次猛然转身“第一次发现”。

看不见的关键信息必须重新选择机位或CUT到独立细节镜头。

## 写入提示词

空间确认后，每条相关提示词包含：

```text
已确认位置：是。
⚠️空间布局：主轴线、人物位置、朝向、相互距离、固定背景、关键道具位置、摄影机所在轴线侧和禁止变化项。
```

示例：

```text
⚠️空间布局（已确认）：主轴线由南侧入口指向北侧床榻。角色A位于房间中央木桩处，身体朝北偏东门口；角色B站在北侧门口，面向角色A；C1位于轴线西侧拍角色A三分之二正面，C2仍在轴线西侧，从角色A左肩外拍门口。禁止交换角色左右，禁止把C2移到轴线东侧，禁止让角色A为露脸转向摄影机。
```

## 站位图验证与修复

站位图或分镜生成后逐项比对：

- 实际出场人数和尚未入画者。
- 人物坐标、距离、左右、前后和专属背景。
- 身体朝向、视线目标和180度轴线。
- 摄影机编号、位置、朝向和屏幕关系。
- 持物手、接触点和固定障碍。
- 道具表面、高度、状态和归属。
- 当前机位是否能看到所写关键信息。
- 下一镜是否继承上一镜结束状态。

任一核心项错误，标记为“候选失败”，不得继续作为下游参考。回到空间真源修改，再同步更新：

1. 空间确认图。
2. 完整分镜脚本。
3. 故事板格序。
4. 图片提示词。
5. 视频提示词。
6. 连续性状态表。

不得保留错误参考图，再只在文字中要求模型忽略它。
