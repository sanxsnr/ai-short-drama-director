# 空间判断、站位与连续性

## 唯一职责

本文件是以下内容的唯一规则真源：

- 场景方向、坐标与固定锚点。
- 人物、道具和摄影机的空间位置。
- 人物身体朝向、头部方向、视线目标和屏幕左右。
- 人物相对剧情对象的正面、侧面、背面与移动方向。
- 摄影机实际能看到人物哪一面。
- 关系轴线、运动轴线与摄影机允许区。
- 移动轨迹、遮挡、接触点和物理关系。
- SHOT之间与SEG之间的状态继承。
- 当前景别、光线、焦点和遮挡下的信息可见性。

本文件不负责决定何时CUT、30度规则是否适用、同轴景别路径或相邻SHOT视觉差异是否充分；这些只由`13-cut-shot-geometry.md`定义。

涉及完整分镜、多人互动、关键道具操作、人物移动、正面／侧面／背面描述、过肩／反打／主观机位或跨空间移动时必须读取本文件。若任务同时存在CUT，再读取`13`。

## 优先级

1. 用户本轮明确说明。
2. 已确认的场景资产卡、站位图、坐标和上一SHOT结束状态。
3. 本文件的空间与连续性规则。
4. 可回滚的临时假设。
5. 通用示例。

任何示例方向都不能覆盖用户真实场景。

## 空间确认Gate

执行顺序：

```text
锁定场景结构 → 建立方向或坐标 → 锁定人物和道具位置
→ 锁定剧情对象 → 求解人物朝向、移动向量和摄影机相对方位
→ 推导摄影机实际可见面 → 建立关系轴线与运动轴线
→ 标出摄影机允许区／唯一机位 → 检查遮挡、屏幕左右和信息可见性
→ 输出唯一空间状态 → 交给13设计CUT与机位变化
```

禁止先写“正面中景”“侧面特写”等结果，再倒推人物和摄影机。必须先完成几何求解，再写景别和构图。

禁止先设计好看的机位，再让人物无理由转向摄影机、瞬间移动或改变道具位置。

### A. 已确认

用户已确认场景资产、站位图、坐标、人物朝向、摄影机方位、上一SHOT唯一状态或固定空间设定时，直接继承，不重复提问，也不得额外扩展替代机位。

```text
空间状态：已确认
依据：[具体资产／站位图／上一SHOT／用户确认内容]
唯一方案锁：开启
```

### B. 可唯一推导

资料没有显式坐标，但从固定锚点、剧情对象、动作方向、人物朝向和上一状态只能得到一种合理布局时，内部建立空间表并直接继续，不停机，不提供理论上可拍但不符合原镜头目的的替代方案。

```text
空间状态：可唯一推导
依据：[固定锚点、剧情对象、动作目标、上一SHOT状态]
唯一方案锁：开启
```

### C. 关键歧义

只有同时满足以下条件才停止正式分镜并请求确认：

1. 存在两种以上同样符合用户镜头目的和已锁定事实的合理布局；
2. 不同布局会改变人物左右、轴线、可见面、道具接触或CUT结果。

“理论上还可以从侧面拍”不构成关键歧义。只要用户已经锁定正面反拍、剧情对象方向或镜头目的，其他理论机位自动排除。

不得因无关装饰尺寸、次要家具或可回滚细节停机。可回滚细节必须写成一个明确临时假设，不能写“或”“可能”“大概”。

## 何时必须建立空间图

以下任一条件成立，必须输出或内部建立俯视空间图：

- 两个或更多故事角色互动，即使不同时同框。
- 存在距离、遮挡、追逐、对峙、注视、递交、推拉、攻击或接触关系。
- 存在左、右、前、后、内、外、上下层级或进出路线。
- 出现“正面、侧面、背面、过肩、反打、朝向、后退、远离、靠近”等空间词。
- 关键道具位于具体表面、被拿取或改变归属。
- 机位方向会影响轴线、视线、屏幕左右、人物可见面或信息可见性。
- 从正面切过肩、反打、主观、高低机位或跨越空间节点。

可跳过：

- 单人、无关键道具、无方向要求的纯表情特写。
- 无人物关系的纯环境镜头。
- 无具体位置要求的抽象插入镜头。

跳过时记录原因。

## 场景方向与坐标

优先继承用户提供的场景图、资产卡和固定锚点。不得把“北＝场景深处、南＝入口”等示例当成通用事实。

每个场景单独定义方向，例如：

```text
本场内部方向：
北：圆窗墙
南：卧房门
东：架子床外侧通道
西：低桌与宫灯
```

真实方位未知时，可使用“场景北／场景南”，但必须说明这是本场工作坐标，不代表地理方向。

同时锁定：

- 空间长度、宽度、高度或相对比例。
- 门、窗、床、桌、柱、屏风、楼梯等固定锚点。
- 可通行区与不可穿越的墙体、家具和障碍。
- 关系轴线、运动轴线和摄影机允许区。

用户使用自定义坐标时严格继承，例如：

```text
整体空间：X 00—20，Y 00—15，Z 00—08
椅子：坐标02.12.03，朝东，比例1.0
人物A：坐标05.09.00，朝北
摄影机C1：坐标05.02.02，朝北
```

禁止“左边一点”“大概后面”“肩头或木桩上”等多解状态。

## 人物空间状态

每名人物锁定：

- 绝对坐标或唯一相对位置。
- 与固定锚点和其他人物的距离。
- 当前剧情对象。
- 身体朝向。
- 头部方向和视线目标。
- 移动方向与移动方式：前进、后退、侧移、转身后移动或静止。
- 站、坐、跪、躺、被捆、受伤或支撑状态。
- 前景、中景、后景层级与专属背景。
- 屏幕左右、前后、遮挡和接触关系。

人物朝向由剧情对象和动作目标决定，不由摄影机决定。需要正脸时移动摄影机，不让人物无理由转向镜头。

## 人物—剧情对象—运动—摄影机几何求解

任何包含人物面向、移动或机位方位的SHOT，在写正式分镜或生图提示词前，必须完成本节。不得只凭语言感觉判断“正面”或“侧面”。

### 四个必锁向量

以人物为中心建立四个方向：

```text
T：人物 → 剧情对象
F：人物胸口／鼻尖的身体正面方向
M：人物实际移动方向
C：人物 → 摄影机
```

可以用坐标向量，也可以用唯一的东南西北／前后方向表达。无显式坐标时，内部建立临时工作坐标。

### 第一步：剧情对象与人物面向

先判断人物正在面对谁或什么：床榻、对话者、门、道具、出口或运动目标。

- `F`与`T`同向：人物正面朝剧情对象。
- `F`与`T`近似垂直：人物侧面对剧情对象。
- `F`与`T`反向：人物背对剧情对象。

用户已经写明“胸口、鼻尖、头部与目光始终朝床”，则`F`必须锁向床；摄影机无权改变`F`。

### 第二步：移动方式

比较`M`与`F`：

- `M`与`F`同向：人物向前走。
- `M`与`F`反向：人物保持面向对象向后退。
- `M`与`F`近似垂直：人物横向侧移。
- 人物先改变`F`再移动：转身后离开，必须写出转身过程。

比较`M`与`T`：

- `M`与`T`同向：靠近剧情对象。
- `M`与`T`反向：远离剧情对象。
- `M`与`T`近似垂直：围绕对象横移。

“面向床榻、沿中央通道直线后退、远离床榻”必须同时满足：`F`与`T`同向，`M`与`F`反向，`M`与`T`反向。任一不满足都判定为空间错误。

### 第三步：摄影机实际看到人物哪一面

比较`C`与`F`：

| 摄影机相对人物的位置 | 推导出的画面可见面 |
|---|---|
| `C`与`F`同向 | 正面／近正面 |
| `C`与`F`约30°—60° | 前三分之二侧面 |
| `C`与`F`近似垂直 | 侧面 |
| `C`与`F`约120°—150° | 后三分之二侧面 |
| `C`与`F`反向 | 背面 |

这里的30°—60°用于判断**单个机位相对人物正面能看到哪一面**，不是相邻SHOT之间的30度剪辑规则。相邻SHOT夹角是否适用与是否充分，只由`13`判断。

画面描述必须服从推导结果：

- 摄影机在剧情对象方向、人物正面也朝剧情对象时，摄影机能看到人物正面。
- 摄影机在人物侧面时，不能写正面中景。
- 摄影机在人物背后时，不能写正面或近正面。
- 若镜头目的锁定正面反应，必须把摄影机放到人物正面方向，而不是让人物无动机转向镜头。

### 第四步：视线是否构成“无动机看镜头”

比较人物视线目标方向与`C`：

- 剧情对象与摄影机位于人物同一方向，人物看剧情对象时可以呈现近似直视镜头；这是有剧情动机的视线。
- 摄影机不在剧情对象方向，而人物仍看向摄影机，必须有明确剧情动机，否则判定为无动机看镜头。
- 摄影机仅略偏离剧情对象方向时，人物应看向对象而不是精确盯镜头中心。

不得把“画面看起来正面”误写成“人物在看摄影机”。必须分别记录：`身体朝向对象`、`视线目标对象`、`摄影机位于对象方向`。

### 第五步：唯一方案锁

当以下项目已经共同锁定时，空间方案只有一个：

- 剧情对象；
- 人物身体朝向；
- 人物移动方式与方向；
- 镜头要求看到的人物可见面；
- 摄影机轴线侧或对象方向。

此时必须输出“唯一方案锁：开启”，直接使用唯一合法机位。禁止额外给出侧拍、背拍或其他理论机位，也禁止在九格内部切换到另一套空间方案。

只有上述项目未锁定，且两个方案都同样满足用户镜头目的时，才允许请求确认。

### 强制矛盾检查

以下任一情况直接判定“需返工”，不得进入13或下游提示词：

- 写“正面中景”，但摄影机位于人物侧面或背后。
- 写“人物正面朝床”，实际身体向量没有朝床。
- 写“后退远离床”，实际移动方向是横移、靠近床或先转身。
- 人物没有转身过程，却在连续格中正面方向突然反转。
- 摄影机不在剧情对象方向，却让人物为了露脸看镜头。
- 用户已锁定唯一正面反拍方案，输出中又混入侧拍方案。
- 眼部特写和同轴中景声称同轴，但摄影机方位或轴线侧不同。

### 《聊斋·董生》正面惊退示例

```text
剧情对象T：床榻／阿琐
董生正面F：朝床榻
董生移动M：沿中央通道反向于F，直线后退并远离床榻
摄影机C：位于床榻／阿琐方向，从床边朝房间中央反拍董生
推导可见面：正面／极轻微偏正面
视线判定：董生看床榻，摄影机与床榻同方向，因此近似直视镜头但有剧情动机
唯一方案锁：开启
禁止方案：侧拍、背拍、横移、斜退、转身逃跑
```

这类镜头不能因为“理论上也可以侧拍”而产生第二方案；原镜头目的和空间条件已经唯一确定正面反拍。

## 道具空间状态

关键道具锁定：

- 所在表面或持有人。
- 具体位置、高度和朝向。
- 持物手、接触点和归属。
- 打开、关闭、破损、点燃、倒空等状态。
- 下一SHOT是否仍存在、是否可见。

禁止道具漂浮、无过程换手、无过程消失或出现在错误表面。

## 摄影机空间事实

每个SHOT记录：

- 摄影机编号C1、C2、C3……
- 坐标或相对于人物／场景锚点的位置。
- 朝向、高度和轴线侧。
- `C`与人物正面`F`的关系。
- 推导出的可见面：正面、前三分之二、侧面、后三分之二或背面。
- 摄影机与剧情对象是否位于人物同一方向。
- 主体在屏幕中的左右与前后层级。
- 前景遮挡物与焦点状态。
- 当前机位能看见和不能看见的信息。

本文件只确认摄影机在空间中是否合法、可见面是否与文案一致、是否越轴、是否能看到目标。相邻SHOT是否值得CUT、30度是否适用以及视觉差异路径是否充分，由`13`审核。

## 关系轴线、运动轴线与屏幕方向

### 关系轴线

由互相关注、对话、对峙或接触的两名主体形成。摄影机一旦选择轴线侧，相邻连续SHOT默认保持该侧。

### 运动轴线

由人物或物体的主要运动方向形成。连续SHOT保持屏幕运动方向，除非镜头内完成转向、经过中性机位或重新建立空间。

### 越轴处理

需要越轴时，必须通过以下至少一种方式重新建立空间：

- 摄影机在镜头内穿过轴线。
- 人物走位改变关系轴线。
- 使用明确的中性正面／背面机位。
- 使用空间建立镜头说明新侧别。

禁止直接无理由翻转人物左右、视线方向或运动方向。

## 移动轨迹

移动写成：

```text
起点坐标／功能区 → 身体朝向F → 移动方向M → 移动方式
→ 经过节点／障碍 → 终点坐标／功能区
→ 到达后身体朝向、视线与支撑状态
```

同时写清：

- 身体重心与速度。
- 剧情对象和视线目标。
- 前进、后退、侧移或转身后移动。
- 持物手和支撑关系。
- 绕障方式。
- 到达后的唯一姿态。

## 接触与受力关系

接触动作写成：

```text
执行者 → 手／脚／道具 → 接触目标 → 接触位置
→ 力量方向 → 被作用对象的位移／状态 → 动作后关系
```

不得只写“抓住”“踢开”“递给”而让模型猜测接触点与物理方向。

## 跨SHOT状态继承

连续CUT后的下一SHOT必须继承仍然成立的状态：

- 人物位置与相对距离。
- 剧情对象。
- 身体朝向、头部方向与视线目标。
- 人物可见面与摄影机所在半空间。
- 屏幕左右和运动方向。
- 动作完成程度、速度与发力状态。
- 持物手、支撑手、接触关系和道具归属。
- 坐、站、跪、躺、被捆、醉酒、受伤、虚弱等持续状态。
- 门窗、床幔、灯具、机关与场景道具状态。
- 服装、发型、污渍、雨水、战损与环境光线。
- 已经发生的剧情结果。

下一SHOT起始状态必须同时包含仍存在的旧主体与新主体，不能只描述新出场人物。

禁止：

- 已抬头后重新抬头。
- 已发现目标后重新寻找。
- 仍被捆却无过程自由行动。
- 道具无过程换手。
- 人物无过程跨越床、门、墙或房间。
- 未转身却突然从正面变成背面。
- 未移动摄影机却突然从侧面变成正面。

TIME CUT、明确场景转换、梦境或回忆切换时，原空间坐标与屏幕左右可标记“不适用”，但必须明确哪些人物状态、服装、伤势、道具和剧情结果仍然继承。

状态继承不等于复制上一镜画面、保持同一机位或重演动作。

## 信息可见性

每个SHOT必须检查：

- 当前景别能否看清关键细节。
- 摄影机相对人物方位能否看到声明的人物可见面。
- 光线与逆光是否遮掉面部信息。
- 前景人物是否遮挡主体。
- 虚焦对象是否被错误赋予关键动作。
- 手部、道具和接触点是否在画面内。
- 摄影机是否实际看得到绳结、瞳孔、伤口或机关。

硬规则示例：

- 中远景逆光过肩镜头不能展示瞳孔内部碎片。
- 双手反捆在背后时，人物不能用视线看到背后绳结。
- 虚焦前景不能承担关键动作或关键信息。
- 摄影机位于人物侧面时不能声称看到完整正面。
- 人物已观看完整凝聚过程，下一镜不能再次“第一次发现”。

关键信息不可见时必须重设空间机位；是否通过CUT切到独立细节镜头由`13`决定。

## 写入下游提示词

空间确认后，相关故事板或视频提示词至少包含：

```text
空间状态引用：[场景／SHOT状态编号]
唯一方案锁：开启／关闭
⚠️空间锁：剧情对象、人物位置与正面方向、移动方式与轨迹、摄影机相对方位、推导可见面、轴线侧、屏幕关系和禁止变化项。
```

不得把内部确认问题、ABC导航或Skill调用命令写入生成提示词。

当提示词写“正面／侧面／背面”时，必须同时写明摄影机为何能看到这一面，例如：

```text
董生正面朝床榻；摄影机位于床榻方向，从床边反拍董生，因此画面为正面或近正面。
```

不得只写结论“正面中景”而省略人物正面、剧情对象和摄影机方位关系。

## 本文件自检

- 人数和出场时点正确。
- 坐标、距离、左右、前后和专属背景唯一明确。
- 剧情对象T、人物正面F、移动M和摄影机方向C全部锁定。
- 人物前进、后退、侧移或转身逻辑与F、M一致。
- 与剧情对象的靠近／远离关系与M、T一致。
- 摄影机推导可见面与提示词中的正面／侧面／背面一致。
- 人物近似看镜头时，摄影机确实与剧情对象同方向。
- 唯一方案锁开启时没有混入替代机位。
- 身体朝向、视线、关系轴线与运动轴线成立。
- 摄影机位置、朝向、轴线侧和屏幕关系明确。
- 持物手、支撑手、接触点与固定障碍正确。
- 道具表面、高度、状态和归属正确。
- 当前机位能看到所描述的关键信息。
- 下一SHOT完整继承上一SHOT仍然成立的状态。
- 没有“或”“可能”“大概”等多解状态。

任一核心项错误时，空间状态标记为“需返工”，不得作为下游CUT、故事板或视频提示词的已确认真源。
