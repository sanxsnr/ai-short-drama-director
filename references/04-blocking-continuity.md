# 空间判断、站位与连续性

## 适用范围与优先级

涉及完整分镜、CUT、多人互动、关键道具操作、过肩／反打／主观机位或跨空间移动时，必须读取本文件，并同时读取 `13-cut-shot-geometry.md`。

本文件负责锁定空间事实；`13-cut-shot-geometry.md` 负责决定何时CUT以及下一机位是否成立。

优先级：

1. 用户本轮明确说明。
2. 已确认的场景资产卡、站位图和上一SHOT结束状态。
3. 本文件的空间与连续性规则。
4. 通用示例和临时假设。

任何示例方向都不能覆盖用户真实场景。

## 空间确认Gate

执行顺序：

```text
锁定场景结构 → 建立方向或坐标 → 锁定人物和道具位置
→ 建立关系轴线与运动轴线 → 标出候选摄影机位置
→ 检查可见性、遮挡和屏幕左右 → 才能拆CUT和写提示词
```

禁止先设计好看的机位，再让人物无理由转向摄影机或瞬间移动。

### 三种空间状态

#### A. 已确认

用户已经确认场景资产、站位图、坐标、上一SHOT唯一状态或固定空间设定时，直接继承，不重复提问。

记录：

```text
已确认位置：是，继承自[具体资产／上一SHOT／用户确认内容]。
```

#### B. 可唯一推导

资料没有显式坐标，但从固定锚点、动作目标和上一状态只能得到一种合理布局时，内部建立空间表并直接继续，不停机。

记录：

```text
已确认位置：可唯一推导。
推导依据：[固定锚点、动作目标、上一SHOT状态]。
```

#### C. 关键歧义

只有当存在两种以上合理布局，而且不同布局会改变人物左右、轴线、可见性、道具接触或CUT结果时，才输出位置确认并停止正式分镜。

不得因为缺少无关装饰尺寸、次要家具或可回滚细节而停机。可回滚细节使用明确临时假设并继续。

## 何时必须建立空间图

以下任一条件成立，必须输出或内部建立俯视调度图：

- 两个或更多故事角色互动，即使不同时同框。
- 存在距离、遮挡、追逐、对峙、注视、递交、推拉、攻击或接触关系。
- 存在左、右、前、后、内、外、上下层级或进出路线。
- 关键道具需要位于具体表面、被拿取或改变归属。
- 机位方向会影响轴线、视线、屏幕左右或信息可见性。
- CUT从正面切过肩、反打、主观、高低机位或跨越空间节点。

可以跳过：

- 单人且无关键道具、无方向要求的纯表情特写。
- 无人物关系的纯环境镜头。
- 无具体位置要求的抽象插入镜头。

跳过时记录原因。

## 场景方向与坐标

优先继承用户提供的场景图、资产卡和固定锚点。不得把“北＝场景深处、南＝入口”等示例当成通用事实。

每个场景必须单独定义方向，例如：

```text
本场方向定义：
北：实际北侧墙／圆窗
南：卧房门
东：架子床外侧通道
西：低桌与宫灯
```

若真实方位未知，可使用“场景北／场景南”作为工作坐标，但必须说明它只是本场内部方向，不代表地理北方。

同时记录：

- 场景长度、宽度、高度或相对比例。
- 门、窗、床、桌、柱、屏风、楼梯等固定锚点。
- 关系轴线和运动轴线。
- 摄影机允许活动区。
- 不可穿越的墙体、家具和遮挡物。

若用户使用自定义坐标，严格按其规则，例如：

```text
整体空间：X 00—20，Y 00—15，Z 00—08
椅子：坐标02.12.03，朝东，比例1.0
人物A：坐标05.09.00，朝北
摄影机C1：坐标05.02.02，朝北
```

禁止“左边一点”“大概后面”“肩头或木桩上”等多解状态。

## 人物、道具与摄影机位置

### 人物

每名人物锁定：

- 绝对坐标或唯一相对位置。
- 与固定锚点和其他人物的距离。
- 身体朝向。
- 头部方向和视线目标。
- 站、坐、跪、躺、被捆或支撑状态。
- 前景、中景、后景层级与专属背景。
- 左右、前后、遮挡和接触关系。

人物朝向由动作目标决定，不由摄影机决定。

### 道具

关键道具锁定：

- 所在表面或持有人。
- 具体位置、高度和朝向。
- 持物手、接触点和归属。
- 打开、关闭、破损、点燃、倒空等状态。
- 下一SHOT是否仍可见。

禁止漂浮、无过程换手、无过程消失或出现在错误表面。

### 摄影机

每个SHOT写清：

- 摄影机编号C1、C2、C3……
- 坐标或相对位置。
- 朝向和高度。
- 位于关系轴线哪一侧。
- 景别、角度和必要焦段。
- 主体屏幕位置。
- 前景遮挡物及焦点状态。
- 相比上一机位的角度变化。
- 当前机位能看见和不能看见的信息。

## 空间确认输出格式

出现关键歧义时使用：

```markdown
## 位置关系确认：场景 {N}

**本场方向定义**
- 北：
- 南：
- 东：
- 西：

**固定场景锚点**
- 门／窗／床／桌／柱／屏风：

**人物与道具**
- A／角色名：坐标、朝向、视线、姿态、专属背景。
- B／角色名：
- P1／道具名：表面、位置、高度、状态。

**主要相互位置关系**
- 距离、左右、前后、遮挡、入口和出口。

**候选摄影机**
- SHOT 1／C1：位置、朝向、轴线侧、主体屏幕位置。
- SHOT 2／C2：相比C1的变化。

**需要确认的唯一歧义**
- 方案A：
- 方案B：
- 此差异会影响：
```

随后给出俯视SVG、ASCII、Mermaid或清晰文本图。确认后再写正式分镜。

## 移动轨迹与接触关系

移动写成：

```text
起点坐标／功能区 → 运动方向 → 经过节点／障碍 → 终点坐标／功能区
```

同时写清身体重心、视线、速度、持物手、绕障方式和到达后朝向。

接触动作写成：

```text
执行者 → 手／脚／道具 → 接触目标 → 接触位置 → 力量方向 → 动作后状态
```

不得只写“抓住”“踢开”“递给”而让模型猜测物理关系。

## 相邻镜头机位连续性

所有相邻SHOT同时执行 `13-cut-shot-geometry.md`：

- 同一主体机位角度原则上至少变化30度。
- 禁止相邻机位、相邻景别或近似构图。
- 每次CUT至少改变两个变量，且至少一个是视觉几何变量。
- 摄影机不得无理由越过180度轴线。
- 屏幕左右、视线和运动方向必须连续。
- 从正面切过肩时，写清哪一肩、移动方向和轴线侧。

禁止只写“摄影机在人物背后”。应写：

```text
摄影机从人物左前方移动到左后方约45度，从左肩外侧拍向门口，仍位于关系轴线左侧。
```

## 跨镜与跨段状态继承

连续CUT后的下一SHOT必须继承：

- 人物位置和相对距离。
- 身体朝向、头部方向和视线目标。
- 坐、站、跪、躺、被捆、醉酒、虚弱等状态。
- 持物手、支撑手、接触关系和道具归属。
- 门窗、床幔、灯具和机关状态。
- 未完成动作的方向、速度和进度。
- 主光、色温、环境声和已经发生的剧情结果。

下一SHOT起始状态必须同时包含仍存在的旧主体和新主体。

禁止：

- 已抬头后重新抬头。
- 已发现目标后重新寻找。
- 仍被捆却无过程自由行动。
- 道具无过程换手。
- 人物无过程从床外侧到床内侧。

时间、场景、梦境或回忆转换时，空间坐标和屏幕左右可标记“不适用”，但必须明确哪些人物状态、伤势、服装、道具和剧情结果仍需继承。

生成阶段如需0.5—1.5秒重叠，只作为剪辑把手；最终成片删除重复静帧、动作和台词。状态继承不等于复制上一镜画面或保持同一机位。

## 信息可见性

每个SHOT检查：

- 当前景别能否看清关键细节。
- 逆光是否遮掉面部信息。
- 前景人物是否遮挡主体。
- 虚焦人物是否被错误赋予关键动作。
- 手部、道具和接触点是否在画面内。
- 摄影机是否实际看得到绳结、瞳孔、伤口或机关。

例如：

- 中远景逆光过肩镜头不能展示瞳孔内部碎片。
- 双手反捆在背后时，人物不能用目光看到背后绳结。
- 人物已经观看墙角凝聚过程，下一镜不能再次“第一次发现”。

看不见的关键信息必须重设机位或CUT到独立细节镜头。

## 写入提示词

空间确认后，每条相关提示词包含：

```text
已确认位置：是／可唯一推导／临时可回滚假设。
⚠️空间布局：方向定义、固定锚点、人物位置和朝向、距离、道具位置、摄影机轴线侧以及禁止变化项。
```

不得把内部确认问题、ABC导航或Skill调用命令写入生成提示词。

## 站位图验证与修复

检查：

- 实际人数和尚未入画者。
- 坐标、距离、左右、前后和专属背景。
- 身体朝向、视线和180度轴线。
- 摄影机位置、朝向和屏幕关系。
- 持物手、接触点和固定障碍。
- 道具表面、高度、状态和归属。
- 当前机位是否能看到关键信息。
- 下一SHOT是否继承上一SHOT结束状态。

任一核心项错误，标记“候选失败”，不得作为下游参考。回到空间真源修复，并同步更新完整分镜、故事板、图片提示词、视频提示词和连续性状态表。
