# 空间判断、站位与连续性

## 唯一职责

本文件是以下内容的唯一规则真源：

- 场景方向、坐标与固定锚点。
- 人物、道具和摄影机的空间位置。
- 人物身体朝向、头部方向、视线目标和屏幕左右。
- 关系轴线、运动轴线与摄影机允许区。
- 移动轨迹、遮挡、接触点和物理关系。
- SHOT之间与SEG之间的状态继承。
- 当前景别、光线、焦点和遮挡下的信息可见性。

本文件不负责决定何时CUT、CUT类型、30度规则、景别跨级或两变量规则；这些只由`13-cut-shot-geometry.md`定义。

涉及完整分镜、多人互动、关键道具操作、过肩／反打／主观机位或跨空间移动时必须读取本文件。若任务同时存在CUT，再读取`13`。

## 优先级

1. 用户本轮明确说明。
2. 已确认的场景资产卡、站位图、坐标和上一SHOT结束状态。
3. 本文件的空间与连续性规则。
4. 可回滚的临时假设。
5. 通用示例。

任何示例方向都不能覆盖用户真实场景。

## 空间确认Gate

执行顺序：

```text
锁定场景结构 → 建立方向或坐标 → 锁定人物和道具位置
→ 建立关系轴线与运动轴线 → 标出摄影机允许区／候选机位
→ 检查遮挡、屏幕左右和信息可见性
→ 输出唯一空间状态 → 交给13设计CUT与机位变化
```

禁止先设计好看的机位，再让人物无理由转向摄影机、瞬间移动或改变道具位置。

### A. 已确认

用户已确认场景资产、站位图、坐标、上一SHOT唯一状态或固定空间设定时，直接继承，不重复提问。

```text
空间状态：已确认
依据：[具体资产／站位图／上一SHOT／用户确认内容]
```

### B. 可唯一推导

资料没有显式坐标，但从固定锚点、动作目标和上一状态只能得到一种合理布局时，内部建立空间表并继续，不停机。

```text
空间状态：可唯一推导
依据：[固定锚点、动作目标、上一SHOT状态]
```

### C. 关键歧义

只有同时满足以下条件才停止正式分镜并请求确认：

1. 存在两种以上合理布局；
2. 不同布局会改变人物左右、轴线、可见性、道具接触或CUT结果。

不得因无关装饰尺寸、次要家具或可回滚细节停机。可回滚细节必须写成一个明确临时假设，不能写“或”“可能”“大概”。

## 何时必须建立空间图

以下任一条件成立，必须输出或内部建立俯视空间图：

- 两个或更多故事角色互动，即使不同时同框。
- 存在距离、遮挡、追逐、对峙、注视、递交、推拉、攻击或接触关系。
- 存在左、右、前、后、内、外、上下层级或进出路线。
- 关键道具位于具体表面、被拿取或改变归属。
- 机位方向会影响轴线、视线、屏幕左右或信息可见性。
- 从正面切过肩、反打、主观、高低机位或跨越空间节点。

可跳过：

- 单人、无关键道具、无方向要求的纯表情特写。
- 无人物关系的纯环境镜头。
- 无具体位置要求的抽象插入镜头。

跳过时记录原因。

## 场景方向与坐标

优先继承用户提供的场景图、资产卡和固定锚点。不得把“北＝场景深处、南＝入口”等示例当成通用事实。

每个场景单独定义方向，例如：

```text
本场内部方向：
北：圆窗墙
南：卧房门
东：架子床外侧通道
西：低桌与宫灯
```

真实方位未知时，可使用“场景北／场景南”，但必须说明这是本场工作坐标，不代表地理方向。

同时锁定：

- 空间长度、宽度、高度或相对比例。
- 门、窗、床、桌、柱、屏风、楼梯等固定锚点。
- 可通行区与不可穿越的墙体、家具和障碍。
- 关系轴线、运动轴线和摄影机允许区。

用户使用自定义坐标时严格继承，例如：

```text
整体空间：X 00—20，Y 00—15，Z 00—08
椅子：坐标02.12.03，朝东，比例1.0
人物A：坐标05.09.00，朝北
摄影机C1：坐标05.02.02，朝北
```

禁止“左边一点”“大概后面”“肩头或木桩上”等多解状态。

## 人物空间状态

每名人物锁定：

- 绝对坐标或唯一相对位置。
- 与固定锚点和其他人物的距离。
- 身体朝向。
- 头部方向和视线目标。
- 站、坐、跪、躺、被捆、受伤或支撑状态。
- 前景、中景、后景层级与专属背景。
- 屏幕左右、前后、遮挡和接触关系。

人物朝向由动作目标决定，不由摄影机决定。需要正脸时移动摄影机，不让人物无理由转向镜头。

## 道具空间状态

关键道具锁定：

- 所在表面或持有人。
- 具体位置、高度和朝向。
- 持物手、接触点和归属。
- 打开、关闭、破损、点燃、倒空等状态。
- 下一SHOT是否仍存在、是否可见。

禁止道具漂浮、无过程换手、无过程消失或出现在错误表面。

## 摄影机空间事实

每个SHOT记录：

- 摄影机编号C1、C2、C3……
- 坐标或相对于人物／场景锚点的位置。
- 朝向、高度和轴线侧。
- 主体在屏幕中的左右与前后层级。
- 前景遮挡物与焦点状态。
- 当前机位能看见和不能看见的信息。

本文件只确认摄影机在空间中是否合法、是否越轴、是否能看到目标。相邻机位是否值得CUT以及角度／景别差异是否充分，由`13`审核。

## 关系轴线、运动轴线与屏幕方向

### 关系轴线

由互相关注、对话、对峙或接触的两名主体形成。摄影机一旦选择轴线侧，相邻连续SHOT默认保持该侧。

### 运动轴线

由人物或物体的主要运动方向形成。连续SHOT保持屏幕运动方向，除非镜头内完成转向、经过中性机位或重新建立空间。

### 越轴处理

需要越轴时，必须通过以下至少一种方式重新建立空间：

- 摄影机在镜头内穿过轴线。
- 人物走位改变关系轴线。
- 使用明确的中性正面／背面机位。
- 使用空间建立镜头说明新侧别。

禁止直接无理由翻转人物左右、视线方向或运动方向。

## 移动轨迹

移动写成：

```text
起点坐标／功能区 → 运动方向 → 经过节点／障碍
→ 终点坐标／功能区 → 到达后身体朝向与视线
```

同时写清：

- 身体重心与速度。
- 视线目标。
- 持物手和支撑关系。
- 绕障方式。
- 到达后的唯一姿态。

## 接触与受力关系

接触动作写成：

```text
执行者 → 手／脚／道具 → 接触目标 → 接触位置
→ 力量方向 → 被作用对象的位移／状态 → 动作后关系
```

不得只写“抓住”“踢开”“递给”而让模型猜测接触点与物理方向。

## 跨SHOT状态继承

连续CUT后的下一SHOT必须继承仍然成立的状态：

- 人物位置与相对距离。
- 身体朝向、头部方向与视线目标。
- 屏幕左右和运动方向。
- 动作完成程度、速度与发力状态。
- 持物手、支撑手、接触关系和道具归属。
- 坐、站、跪、躺、被捆、醉酒、受伤、虚弱等持续状态。
- 门窗、床幔、灯具、机关与场景道具状态。
- 服装、发型、污渍、雨水、战损与环境光线。
- 已经发生的剧情结果。

下一SHOT起始状态必须同时包含仍存在的旧主体与新主体，不能只描述新出场人物。

禁止：

- 已抬头后重新抬头。
- 已发现目标后重新寻找。
- 仍被捆却无过程自由行动。
- 道具无过程换手。
- 人物无过程跨越床、门、墙或房间。

TIME CUT、明确场景转换、梦境或回忆切换时，原空间坐标与屏幕左右可标记“不适用”，但必须明确哪些人物状态、服装、伤势、道具和剧情结果仍然继承。

状态继承不等于复制上一镜画面、保持同一机位或重演动作。

## 信息可见性

每个SHOT必须检查：

- 当前景别能否看清关键细节。
- 光线与逆光是否遮掉面部信息。
- 前景人物是否遮挡主体。
- 虚焦对象是否被错误赋予关键动作。
- 手部、道具和接触点是否在画面内。
- 摄影机是否实际看得到绳结、瞳孔、伤口或机关。

硬规则示例：

- 中远景逆光过肩镜头不能展示瞳孔内部碎片。
- 双手反捆在背后时，人物不能用视线看到背后绳结。
- 虚焦前景不能承担关键动作或关键信息。
- 人物已观看完整凝聚过程，下一镜不能再次“第一次发现”。

关键信息不可见时必须重设空间机位；是否通过CUT切到独立细节镜头由`13`决定。

## 空间状态输出格式

```markdown
## 空间状态：场景／SHOT范围

- 状态：已确认／可唯一推导／关键歧义
- 依据：
- 本场方向定义：
- 固定场景锚点：
- 可通行区／障碍：
- 关系轴线：
- 运动轴线：
- 摄影机允许区：

### 人物
- 角色A：坐标／相对位置、朝向、视线、姿态、屏幕侧、背景、持续状态。
- 角色B：

### 道具
- P1：表面／持有人、坐标、高度、朝向、状态、归属、可见性。

### 摄影机事实
- C1／SHOT X：位置、朝向、高度、轴线侧、屏幕关系、可见／不可见信息。

### 跨镜状态
- 上一SHOT结束状态：
- 下一SHOT必须继承：
- 允许变化：
- 禁止变化：
```

出现关键歧义时，额外输出唯一需要确认的A／B方案与影响范围，并附俯视SVG、ASCII、Mermaid或清晰文本图。

## 写入下游提示词

空间确认后，相关故事板或视频提示词至少包含：

```text
空间状态引用：[场景／SHOT状态编号]
⚠️空间锁：固定锚点、人物位置与朝向、道具位置、摄影机轴线侧、屏幕关系和禁止变化项。
```

不得把内部确认问题、ABC导航或Skill调用命令写入生成提示词。

## 本文件自检

- 人数和出场时点正确。
- 坐标、距离、左右、前后和专属背景唯一明确。
- 身体朝向、视线、关系轴线与运动轴线成立。
- 摄影机位置、朝向、轴线侧和屏幕关系明确。
- 持物手、支撑手、接触点与固定障碍正确。
- 道具表面、高度、状态和归属正确。
- 当前机位能看到所描述的关键信息。
- 下一SHOT完整继承上一SHOT仍然成立的状态。
- 没有“或”“可能”“大概”等多解状态。

任一核心项错误时，空间状态标记为“需返工”，不得作为下游CUT、故事板或视频提示词的已确认真源。
