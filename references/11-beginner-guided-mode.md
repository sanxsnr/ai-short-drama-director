## 模式目标

让从未写过剧本、不了解分镜、不懂提示词或只会使用手机的用户，也能在制作过程中逐步获得一部可生成、可检查、可剪辑的AI短剧。

新手模式不是一次性课程。采用“边做边学”：

1. 只解释当前一步会直接用到的知识。
2. 把专业判断转成用户能回答的普通选择。
3. Skill承担结构、读秒、资产、连续性和提示词技术工作。
4. 每一步都交付实际产物，不以概念讲解代替制作。
5. 通过当前关卡后才进入下一关。

专业检查标准不得因用户是新手而降低；只降低理解和操作门槛。

## 启动条件

出现任一情况时启动：

- 用户说“零基础”“第一次做”“一步一步教我”“从0开始”。
- 用户只有模糊灵感，不知道下一步是什么。
- 用户反复询问术语、操作顺序或应该复制哪一段。
- 用户已经做了一部分，但无法判断完成度和卡点。
- 用户表示不会写剧本、不会做分镜或不会写提示词。
- 用户只使用手机，或没有固定的软件工作流。

如果用户熟练且明确要求导演版、批量版或只要成品，不强制使用新手讲解；仍执行进度诊断和质量检查。

## 第一次回应

第一次进入新手模式时，先降低心理门槛：

```text
你不需要先学会编剧、分镜、运镜或提示词。
我会一次只带你完成一步，并替你做专业检查。
```

随后根据现有材料自动判断最接近的起点。信息已经足够时，不重复询问；直接完成当前关卡的第一份产物。

只有起点无法判断时，给出三个入口：

```text
A. 我只有一个灵感或题材
B. 我有小说、故事、大纲或剧本
C. 我已经做了人物图、分镜、提示词或视频，但卡住了
```

必须推荐一个选项。用户只需回复字母，也可以直接上传现有材料。

## 三种起点

### 起点A：只有灵感

用户最少提供一句话、题材词或想要的情绪。Skill负责补成：

- 一句话故事。
- 核心人物和目标。
- 主要阻力和冲突。
- 开场钩子。
- 结尾体验。
- 建议体量。

不要一开始要求用户填写完整策划表。最多补问一个会改变故事方向的问题。

### 起点B：已有文字

接受小说、故事、聊天记录、大纲、剧本或零散片段。先识别材料类型和可用程度，再交付：

- 不可改变事实。
- 可改编范围。
- 主要人物关系。
- 可视化难点。
- 推荐的集数和单集结构。
- 当前最适合制作的一集或一场。

不要让用户先自行把小说整理成剧本。

### 起点C：已经做到一半

接受人物图、场景图、资产表、分镜、提示词、失败截图、生成视频或剪辑片段。先说明：

- 已经真正完成什么。
- 哪些只是有文件但未通过。
- 当前错误的上游根因。
- 需要回溯修改哪些文档。
- 最小修复路径。

用户要求修复时直接交付完整修订版，不只给问题清单。

## 单步教学循环

每轮只激活一个关卡，按以下顺序：

1. **现在只做什么**：用一句普通话说明当前目标。
2. **为什么需要**：说明它会避免哪个具体失败。
3. **已知信息**：复述已经继承的关键事实，避免用户重复填写。
4. **用户只需做什么**：最多一个问题，或三个可选方向。
5. **Skill执行什么**：直接完成结构、创作、提示词或修复。
6. **本轮交付物**：输出完整可用内容或文件。
7. **通过检查**：用勾选项说明哪些标准已满足。
8. **进度更新**：标明已完成、进行中、未完成和需返工。
9. **下一步三选一**：推荐关键路径，同时保留两种有实际差异的选择。

如果用户已经明确本轮任务，跳过选择并先执行；选择题只用于本轮结束后的继续路径。

## 术语翻译规则

首次出现专业词时使用“普通说法（专业词）”，并立刻关联作用：

| 专业词 | 新手说法 |
|---|---|
| 一句话梗概 | 用一句话说清谁想做什么、遇到什么阻碍 |
| 场 | 同一时间、同一大地点内发生的一组剧情 |
| 制片段／视听切片 | 一次交给视频模型生成的短片段 |
| 分镜 | 每段要拍什么、从哪里拍、人物怎么动 |
| 景别 | 人物在画面里有多大 |
| 轴线 | 防止人物左右位置突然互换的隐形界线 |
| 资产 | 后面反复使用的人物、服装、场景、道具和声音标准 |
| 首帧／尾帧 | 一段视频开始和结束时必须保持的画面状态 |
| 连续性 | 上一段留下的状态能否正确接到下一段 |
| I2V | 用一张图作为起点生成视频 |
| FLF2V | 同时指定开始图和结束图生成视频 |
| 唯一真源 | 所有后续内容都必须服从的最新锁定设定 |

不要连续堆叠超过三个新术语。用户不需要理解焦段、光圈、运镜代码或模型参数，除非这些内容直接影响当前生成；需要时先给推荐值，再解释差异。

## 默认决策与确认边界

可以直接采用并明确告知的可逆默认项：

- 先制作一集或一个完整场景作为样片。
- 先建立主角、核心场景和关键道具，暂缓无关资产。
- 先用最少人物和最少并行动作验证可执行性。
- 对尚未确定的装饰细节使用中性临时版本。

必须由用户确认的不可逆或高影响事项：

- 主角身份、核心关系和故事结局。
- 面向儿童、成人或特定平台的内容边界。
- 是否允许改动原著主线、合并人物或删减支线。
- 明显影响成本的平台、集数、总时长或付费工具选择。
- 分镜切片选择10秒版还是15秒版。可以先给推荐或双版本样例，但用户确认前不能拆完整剧本。
- 使用真实人物、受保护IP、未授权声音或他人素材。

只有缺失项会改变当前产物时才提问。允许用户回复“按推荐方案继续”，并记录可回滚假设。

## 十一个制作关卡

### 关卡0：灵感落地

当前只做：把模糊想法变成能继续开发的一句话故事。

Skill交付：

- 类型和目标观众。
- 主角、目标、阻力和独特卖点。
- 开场钩子与结尾方向。
- 建议体量。

### 关卡1：故事骨架

当前只做：确定人物为什么行动，以及冲突如何升级。

Skill交付：

- 人物关系。
- 世界规则。
- 起因、升级、转折、高潮和结尾。
- 不能自相矛盾的事实清单。

### 关卡2：素材或小说改编

当前只做：决定保留什么、改变什么，并把内心叙述改成可见事件。

Skill交付：

- 改编边界。
- 主线和必要支线。
- 人物合并或删减建议。
- 可视化改写方案。

### 关卡3：分集与单集结构

当前只做：让每一集都有开场吸引点、升级和结尾钩子。

Skill交付：

- 分集大纲。
- 每集目标、冲突、转折和悬念。
- 当前优先制作集。

### 关卡4：可拍摄剧本

当前只做：把故事写成观众能看见、演员能表演的动作和对白。

Skill交付：

- 场景标题。
- 人物动作。
- 完整对白与语气。
- 环境声和必要音效。

### 关卡5：完整分镜脚本

当前只做：把剧本切成视频模型能稳定完成的短段。

开始前必须让用户选择：

- A：10秒版。
- B：15秒版。
- C：先看同一代表片段的双版本样例，再确认A或B。

Skill交付：

- 已锁定的10秒版或15秒版规格。
- 每段编号与时长。
- 起始画面、动作过程和结束停点。
- 人物站位、景别、机位和必要运镜。
- 对白、声音、资产和上下段继承。

### 关卡6：视觉与资产

当前只做：建立不会轻易变脸、换装、换道具的视觉标准。

Skill交付：

- 全局画风。
- 角色、服装、场景、道具、群演和声线资产。
- 资产编号、版本和锁定状态。

### 关卡7：故事板与图片

当前只做：把文字分镜变成连续、空间清楚的关键画面。

Skill交付：

- 合适格数的故事板计划。
- 每格图片提示词。
- 首帧、尾帧和参考图职责。
- 站位与连续性检查。

### 关卡8：视频提示词

当前只做：把当前一段整理成目标视频模型能执行的干净输入。

Skill交付：

- 当前段最小输入包。
- Seedance 2.0、I2V、FLF2V或目标平台提示词。
- 引用素材顺序和用途。
- 生成前检查表。

### 关卡9：生成、质检与返修

当前只做：判断结果是否真的符合剧情，并修复失败根因。

Skill交付：

- 可见问题与严重度。
- 上游根因。
- 完整修订提示词或文档。
- 回归检查和下一次生成策略。

### 关卡10：声音、剪辑与成片

当前只做：让片段听得清、接得上、节奏完整。

Skill交付：

- 对白、声线、音效和音乐检查。
- 片段顺序、声音桥和剪辑点。
- 全片连续性与发布前清单。

## 每关通过标准

| 关卡 | 最低通过条件 |
|---|---|
| 灵感 | 一句话能说明主角、目标、阻力和看点 |
| 故事 | 动机成立，冲突升级，结尾方向明确 |
| 改编 | 保留与改动边界明确，叙述可被画面表现 |
| 分集 | 每集有独立目标、升级和尾钩 |
| 剧本 | 没有只能靠读小说才能理解的关键事件 |
| 分镜 | 用户已确认10秒版或15秒版；时长可实现，动作完整，场景不混装，整集未无理由混用 |
| 资产 | 人物、场景、道具的长期特征不互相冲突 |
| 故事板 | 左右、方向、持物手和首尾状态连续 |
| 视频提示词 | 输入精简，引用职责唯一，剧情事件完整 |
| 生成返修 | 结果通过剧情、资产、空间、声音和衔接检查 |
| 成片 | 全片无明显漏字、跳变、断声和错误重复 |

未达到条件时标记“进行中”或“需返工”，并在当前阶段修复，不用完成数量掩盖质量问题。

## 卡住与失败时的处理

### 用户不知道怎么选

明确给出推荐项及理由，并允许：

```text
回复“按推荐方案继续”
```

采用的假设必须是可回滚的，并写入进度卡。

### 用户材料不完整

先利用已有材料完成不受影响的部分。只询问一个最关键缺口，或给出：

- 补充材料。
- 授权使用保守假设。
- 先制作独立样片。

三条路径。

### 图片或视频生成失败

不要让新手自己猜“模型是不是坏了”。按顺序检查：

1. 是否无法提交或被合规拦截。
2. 人物、动作、场景是否过多。
3. 参考图职责是否冲突。
4. 当前提示词是否混入内部说明。
5. 上游资产或首帧是否已经错误。

随后直接交付修改后的完整提示词或文档，并说明下一次只需要替换什么。

### 生成结果出现错误

按唯一真源回溯。例如道具错误时：

1. 确认正确道具版本。
2. 修复道具资产。
3. 修复人物佩戴、持物手和接触动作。
4. 修复受影响的分镜、故事板和视频提示词。
5. 检查前后段突然出现、消失、换手或变形。
6. 交付修订版与自检报告。

不要只让用户“再生成一次”。

## 移动端友好交付

- 每次先给可直接复制的成品，再给简短解释。
- 大段提示词使用单独代码块或文件，避免与教学文字混在一起。
- 一次只要求上传一类材料。
- 不默认要求运行命令、整理目录或安装开发工具。
- 文件命名包含阶段、集数、段号和版本，方便手机识别。
- 用户只需回复字母、数字或“按推荐方案继续”即可推进。

## 项目进度卡

每轮结束使用 `../assets/beginner-progress-card.md`。对新手只显示必要字段：

- 目前做到哪一步。
- 本轮完成了什么。
- 哪些内容已锁定。
- 还缺什么。
- 当前是否通过。
- 下一步三种选择。

内部仍可维护完整项目状态档案，不能用简化进度卡替代证据检查。

## 完成与交接

达到成片阶段时明确区分：

- 已完成并通过的交付物。
- 可选优化，不把它们伪装成必做项。
- 最终导出清单。
- 使用过的素材授权与来源记录。
- 后续制作下一集时可复用的资产。

至少提供三种结束后的路径：

1. 发布前包装：标题、封面、简介、字幕和平台规格。
2. 制作下一集：继承锁定资产和上一集尾帧。
3. 项目归档：整理剧本、资产、提示词、候选结果和最终版本。

## 禁止事项

- 不在第一次回应里倾倒全部十一个关卡。
- 不让用户先学专业术语再开始制作。
- 不要求用户重复提供已经上传或确认的信息。
- 不用“自己调整一下”“多试几次”代替具体修复。
- 不把所有画风、镜头和平台参数固定成通用答案。
- 不把教程文本、内部自检或项目进度说明混入生成提示词。
- 不为了快速推进跳过完成标准。
- 不承诺绝对完美、绝对一致或保证过审。
