## 目标

让同一项目在多轮对话、多集制作和多人协作时保持稳定结构。所有回答都必须让用户一眼看见：

1. 本轮拿到了什么。
2. 项目现在做到哪里。
3. 哪些内容已经通过，哪些仍未完成或需返工。
4. 下一步可以从哪三个明确方向中选择。
5. 用户复制任一A／B／C选项时，文本开头已经包含Skill调用命令。

固定的是信息结构，不是用户题材、画风、画幅、镜头数量或平台参数。

## 固定回答外壳

每次面向用户的最终回复按以下顺序：

```markdown
## 本轮结果

直接回答问题，或提供本轮完成的正文、提示词、文件与核心结论。

## 进度更新

- 当前阶段：
- 已完成：
- 进行中：
- 未完成：
- 需返工／阻塞：

## 自检结论

- 结论：已通过／进行中／需返工／被阻塞
- 检查依据：

## 下一步请选择

A（推荐）：使用 $ai-short-drama-director，选择A：……
B：使用 $ai-short-drama-director，选择B：……
C：使用 $ai-short-drama-director，选择C：……
```

短回答允许压缩，但四个部分不得缺少。长回答先交付成品，再解释进度。

用户只要提示词、XML、JSON或代码时：

1. 可复制内容单独放在代码块或对应标签中。
2. 进度、自检和A/B/C放在内容之外。
3. 不把对话导航、教学说明、Skill调用命令或检查日志混入模型输入。

用户只要文件时：

1. 先给完整文件。
2. 用短句说明本轮修订、进度和自检。
3. 回复末尾仍提供A/B/C三个选择，并让每个可复制回复以Skill调用命令开头。

## 三选一页脚

每次回复结尾固定且只能出现三个选项：

```markdown
## 下一步请选择

### A（推荐）｜动作名称
**调用命令：** `使用 $ai-short-drama-director，选择A：动作名称。`
- 你需要：提供或确认什么。
- 我会：执行什么。
- 你会得到：具体交付物。
- 推荐原因：为什么最能推进关键路径。

### B｜动作名称
**调用命令：** `使用 $ai-short-drama-director，选择B：动作名称。`
- 你需要：
- 我会：
- 你会得到：
- 适用情况：

### C｜动作名称
**调用命令：** `使用 $ai-short-drama-director，选择C：动作名称。`
- 你需要：
- 我会：
- 你会得到：
- 适用情况：
```

强制规则：

- 编号只能是A、B、C，不增加D，不减少为两个。
- 恰好一个选项标记“推荐”。
- 三个选项必须产生不同动作或交付物。
- 推荐项优先解除最大阻塞或完成最近里程碑。
- 用户已指定本轮任务时先执行，再把A/B/C用于下一轮。
- 自然路径不足三个时，第三项使用有意义的“对照样例、先行质检或保守假设”路径，不用同义句凑数。
- 存在阻塞时，可分别提供“补充材料、按可回滚假设继续、先回查上游真源”三条路径。
- 每个选项的第一条可复制文本必须以 `使用 $ai-short-drama-director` 开头。
- 不再只写“直接回复A／B／C”。必须给出完整调用命令。

## Skill调用命令规则

### 标准命令

```text
使用 $ai-short-drama-director，选择A：具体动作。
```

B、C同理。

### 移动端压缩格式

```markdown
A（推荐）：使用 $ai-short-drama-director，选择A：先修复完整分镜。
B：使用 $ai-short-drama-director，选择B：先建立空间站位图。
C：使用 $ai-short-drama-director，选择C：先做代表片段对照样例。
```

### 禁止格式

以下格式不得作为最终ABC回复指令：

```text
A
回复A
A：继续
选择B
```

原因：这些文本没有显式调用Skill，跨会话或复制使用时可能无法稳定进入正确工作流。

### 命令与生成负载隔离

Skill调用命令属于对话导航，必须放在：

- 图片提示词代码块之外。
- 视频提示词代码块之外。
- XML、JSON和API负载之外。
- 制作文档正文之外，除非文档专门记录操作说明。

## 分镜段落标准

一次交给视频模型生成的10秒或15秒单元称为“分镜段落”或“制片段”；段落内部的连续摄影机记录称为“SHOT”；SHOT之间通过CUT连接。

先按 `04-blocking-continuity.md` 锁空间，再按 `13-cut-shot-geometry.md` 审核CUT，最后封装为制片段。

每个分镜段落固定使用以下结构：

```markdown
# EP02｜分镜段落 SEG012｜10秒版

## 1. 基础信息

| 字段 | 内容 |
|---|---|
| 所属剧集 | EP02 |
| 分镜编号 | SEG012 |
| 目标规格 | 10秒版 |
| 预估时长 | 10秒 |
| 剧情功能 | 本段改变了什么 |
| 场景 | SC003（场景名称） |

## 2. 出场资产与连续性

| 类型 | 编号／名称 | 当前状态 | 位置／使用方式 |
|---|---|---|---|
| 人物 | CH001（人物名） | 服装、临时状态 | 坐标、朝向、视线 |
| 道具 | PR003（道具名） | 完整、打开、损坏等 | 持物手、表面、高度或场内位置 |

- 已确认位置：
- 上一段继承：
- 本段起始状态：
- 本段尾帧：
- 下一段继承：

## 3. 时间轴执行表

| 时间码 | SHOT | 画面与动作 | CUT点／类型 | 表演／台词／声音 | 景别／机位／轴线侧／运镜 |
|---|---:|---|---|---|---|
| 00:00–00:03 | 1 |  |  |  |  |
| 00:03–00:07 | 2 |  |  |  |  |
| 00:07–00:10 | 3 |  |  |  |  |

## 4. 生成与参考

- 全局风格：
- 参考素材及唯一职责：
- 故事板／图片提示词：
- 视频提示词：

## 5. 本段自检

- [ ] 总时长符合已锁定的10秒版或15秒版。
- [ ] 时间码首尾相接，没有重叠或空洞。
- [ ] 所有自然CUT点已按规则拆分，没有过载SHOT。
- [ ] 每个CUT已标明合法视觉差异路径，没有无意近似跳切。
- [ ] 30度规则仅在适用时检查；同轴大景别、主体／视角变化或组合差异已写明依据。
- [ ] 动作匹配CUT的方向、速度和进度连续。
- [ ] 人物、服装、场景、道具与锁定资产一致。
- [ ] 左右、视线、持物手、运动方向和空间轴线连续。
- [ ] 当前景别、光线和遮挡能展示所写关键信息。
- [ ] 起始状态与上一段相接，尾帧可被下一段继承。

结论：已通过／需返工／被阻塞。
```

编号规则：

- 新项目建议使用 `EP`、`SEG`、`SHOT`、`SC`、`CH`、`PR`、`VO` 前缀。
- 已有项目沿用原编号，不为了套模板擅自重编号。
- 所有分镜连续输出，不用“同上”“其余同理”“以此类推”。
- 时间轴行数由内容和合法CUT点决定，不固定为三镜。

## 不同文档的正文要求

| 文档类型 | 正文必须包含 |
|---|---|
| 灵感／故事方案 | 一句话梗概、主角目标、阻力、代价、卖点、开场钩子、结尾体验 |
| 小说改编方案 | 不可改变事实、授权范围、主线、必要支线、人物关系、可视化改写、分集建议 |
| 可拍摄剧本 | 场景标题、出场人物、剧情目的、可见动作、完整对白、环境声和必要音效 |
| 完整分镜脚本 | 已确认规格、空间图、SHOT、CUT点、机位几何、资产与连续性、时间轴、声音和自检 |
| 资产设定集 | 资产编号、版本、状态、长期视觉特征、物理结构、临时状态分离、生成提示词 |
| 故事板／生图提示词 | 段落目标、格数依据、每格画面、左右与空间、首尾状态、参考职责、负面约束 |
| 视频提示词包 | 目标模型、当前段最小输入、引用顺序、纯净提示词、起始和结束状态、生成前检查 |
| 质检／返修报告 | 可见问题、严重度、上游根因、波及文件、完整修订、回归检查、仍需确认事项 |

## 移动端与文件规则

- 元数据使用两列表格，不使用“字段名一行、值再一行”的长纵向清单。
- 时间信息使用时间轴表，避免把景别、焦段、机位和运镜拆到远距离段落。
- 提示词使用单独代码块，说明文字不得插入代码块中间。
- A/B/C使用移动端压缩格式时，每个选项仍必须包含完整Skill调用命令。
- 文件名使用 `{项目}_{EPxx或范围}_{文档类型}_Vx.y_YYYYMMDD`。
- 修订文件增加 `_修订自检版`，保留旧版，不覆盖唯一真源。

## 交付前检查

- [ ] 回答是否包含本轮结果、进度更新、自检结论和下一步选择。
- [ ] 是否恰好只有A、B、C三个选项。
- [ ] 是否恰好一个推荐项，且推荐理由与当前阻塞一致。
- [ ] 每个A/B/C选项的可复制文本是否以 `使用 $ai-short-drama-director` 开头。
- [ ] 是否删除了“只回复A／B／C”的旧格式。
- [ ] Skill调用命令是否留在生成提示词、XML、JSON和模型负载之外。
- [ ] 制作文档是否使用固定文档外壳。
- [ ] 分镜是否区分SEG、SHOT和CUT。
- [ ] 分镜是否包含空间确认、CUT点、机位几何、资产、时间轴、声音、首尾状态和自检。
- [ ] 是否消除了字段名和值各占一行的冗长排版。
