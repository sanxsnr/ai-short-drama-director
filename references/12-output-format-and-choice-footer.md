## 目标

让同一项目在多轮对话、多集制作和多人协作时保持稳定结构。所有回答都必须让用户一眼看见：

1. 本轮拿到了什么。
2. 项目现在做到哪里。
3. 哪些内容已经通过，哪些仍未完成或需返工。
4. 下一步可以从哪三个明确方向中选择。

固定的是信息结构，不是用户的题材、画风、画幅、镜头数量或平台参数。

## 固定回答外壳

每次面向用户的最终回复按以下顺序：

```markdown
## 本轮结果

直接回答问题，或提供本轮完成的正文、提示词、文件与核心结论。

## 进度更新

- 当前阶段：
- 已完成：
- 进行中：
- 未完成：
- 需返工／阻塞：

## 自检结论

- 结论：已通过／进行中／需返工／被阻塞
- 检查依据：

## 下一步请选择

A（推荐）：……
B：……
C：……
```

短回答允许压缩为一至两行，但四个部分不得缺少。长回答先交付成品，再解释进度。

用户只要提示词、XML、JSON或代码时：

1. 可复制内容单独放在代码块或对应标签中。
2. 进度、自检和A/B/C放在内容之外。
3. 不把对话导航、教学说明或检查日志混入模型输入。

用户只要文件时：

1. 先给完整文件。
2. 用短句说明本轮修订、进度和自检。
3. 回复末尾仍提供A/B/C三个选择。

## 三选一页脚

每次回复结尾固定且只能出现三个选项：

```markdown
## 下一步请选择

### A（推荐）｜动作名称
- 你需要：提供或确认什么。
- 我会：执行什么。
- 你会得到：具体交付物。
- 推荐原因：为什么最能推进关键路径。
- 直接回复：`A`

### B｜动作名称
- 你需要：
- 我会：
- 你会得到：
- 适用情况：
- 直接回复：`B`

### C｜动作名称
- 你需要：
- 我会：
- 你会得到：
- 适用情况：
- 直接回复：`C`
```

强制规则：

- 编号只能是A、B、C，不增加D，不减少为两个。
- 恰好一个选项标记“推荐”。
- 三个选项必须产生不同的动作或交付物。
- 推荐项优先解除最大阻塞或完成最近里程碑。
- 用户已指定本轮任务时先执行，再把A/B/C用于下一轮。
- 自然路径不足三个时，第三项使用有意义的“对照样例、先行质检或保守假设”路径，不用同义句凑数。
- 存在阻塞时，可分别提供“补充材料、按可回滚假设继续、先回查上游真源”三条路径。
- 移动端回复可把每个选项压缩到一至三行，但必须保留用户动作、Skill动作和交付物。

## 制作文档外壳

用户要求完整文档、导演版或可交接产物时，使用以下固定顺序：

```markdown
# {项目名}｜{集数或范围}｜{文档类型}

## 文档信息

| 字段 | 内容 |
|---|---|
| 项目 |  |
| 集数／范围 |  |
| 文档类型 |  |
| 版本 |  |
| 日期 |  |
| 目标平台／工具 |  |
| 画幅 | 待确认／具体值／不适用 |
| 分镜规格 | 未选择／10秒版／15秒版／不适用 |
| 当前状态 | 草稿／候选／已锁定／修订自检版 |

## 进度摘要

| 类别 | 内容 |
|---|---|
| 已完成 |  |
| 进行中 |  |
| 未完成 |  |
| 需返工／阻塞 |  |

## 正文

按文档类型填写完整内容。

## 自检报告

| 检查项 | 结论 | 依据／问题 |
|---|---|---|
| 内容完整性 | 通过／未通过／不适用 |  |
| 剧情与对白 | 通过／未通过／不适用 |  |
| 时长与镜头 | 通过／未通过／不适用 |  |
| 人物／服装／场景／道具 | 通过／未通过／不适用 |  |
| 空间与连续性 | 通过／未通过／不适用 |  |
| 平台可执行性 | 通过／未通过／不适用 |  |

## 修订记录

| 版本 | 修改范围 | 修改原因 | 自检结果 |
|---|---|---|---|
|  |  |  |  |

## 待办与阻塞

- 无／具体事项。
```

文档内没有信息的字段写“待确认”“无”或“不适用”，不留空白让下游猜测。用户要求纯净成品时，把进度、自检和修订记录放入单独的自检文档。

## 剧本与分镜CSV标准

一次交给视频模型生成的10秒或15秒单元称为“分镜段落”或“制片段”；段落内部的机位切换称为“段内镜头”。不要把整个10秒段和其中一个镜头都叫“镜头012”。

可拍摄剧本固定使用：

```csv
"项目","剧集","场次编号","场次顺序","内外景","场景编号","场景名称","时间","出场人物","剧情目的","节拍编号","可见动作","说话人","语气状态","对白","环境声","关键音效","连续性备注"
```

完整分镜脚本固定使用：

```csv
"项目","剧集","分镜段落编号","分镜规格","段落时长秒","剧情功能","场景编号","段内镜头序号","开始时间码","结束时间码","景别","焦段","机位","运镜","出场人物","人物站位","道具及状态","画面与动作","表演表情","说话人","对白","环境声与音效","上一段继承","动作开始状态","动作完成状态","下一段继承","参考素材职责","Seedance 2.0提示词","自检结论"
```

CSV规则：

- 新项目建议使用 `EP`、`SEG`、`SC`、`CH`、`PR`、`VO` 前缀。
- 已有项目沿用原编号，不为了套模板擅自重编号。
- 每个剧本节拍或段内镜头占一行；段落级信息逐行完整复写。
- 所有单元格使用双引号；单元格内部双引号转义为两个双引号。
- 无值写空字符串，不用“同上”、合并单元格、“其余同理”或“以此类推”。
- 时间轴行数由内容决定；分镜时间码必须连续覆盖整段。
- 短内容输出一个`csv`代码块；长内容主动创建UTF-8 `.csv`文件。

## 不同文档的正文要求

| 文档类型 | 正文必须包含 |
|---|---|
| 灵感／故事方案 | 一句话梗概、主角目标、阻力、代价、卖点、开场钩子、结尾体验 |
| 小说改编方案 | 不可改变事实、授权范围、主线、必要支线、人物关系、可视化改写、分集建议 |
| 可拍摄剧本 | 使用固定CSV表头；包含场景、人物、剧情目的、节拍、可见动作、完整对白和声音 |
| 完整分镜脚本 | 使用固定CSV表头；包含10秒／15秒规格、时间码、资产、站位、动作状态、声音、Seedance提示词和自检 |
| 资产设定集 | 资产编号、版本、状态、长期视觉特征、物理结构、临时状态分离、生成提示词 |
| 故事板／生图提示词 | 段落目标、工具路由、每格画面或站位、左右与空间、动作状态、参考职责、负面约束 |
| 视频提示词包 | Seedance 2.0、当前段最小输入、`@`引用顺序、纯净提示词、动作状态和生成前检查 |
| 质检／返修报告 | 可见问题、严重度、上游根因、波及文件、完整修订、回归检查、仍需确认事项 |

## 移动端与文件规则

- 剧本和分镜使用CSV，不使用Markdown长表或“字段名一行、值再一行”的纵向清单。
- 时间信息放在同一CSV行的开始／结束时间码字段中。
- 一段只描述一个10秒或15秒制片单元；多个段落按编号连续排列。
- 长文档中的每个分镜段落建议从新页开始；同一段内部不强制分页。
- 提示词使用单独代码块，说明文字不得插入代码块中间。
- 文件名使用 `{项目}_{EPxx或范围}_{文档类型}_Vx.y_YYYYMMDD`。
- 修订文件增加 `_修订自检版`，保留旧版，不覆盖唯一真源。

## 交付前检查

- [ ] 回答是否包含本轮结果、进度更新、自检结论和下一步选择。
- [ ] 是否恰好只有A、B、C三个选项。
- [ ] 是否恰好一个推荐项，且推荐理由与当前阻塞一致。
- [ ] 剧本和分镜是否使用固定CSV表头，其他制作文档是否使用固定文档外壳。
- [ ] 分镜是否区分“分镜段落”和“段内镜头”。
- [ ] 分镜是否包含资产、时间轴、台词声音、动作开始／完成状态和自检。
- [ ] 是否消除了“字段名一行、值一行”的冗长排版。
- [ ] 是否把对话导航留在生成提示词之外。
